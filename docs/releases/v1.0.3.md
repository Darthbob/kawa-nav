The phone battery icon on the dash, still flashing its warning right after connecting, fixed at the source. How KawaNav talks to the bike is unchanged from 1.0.2.

### Fixed
- **The phone battery icon no longer flashes an empty battery at connection**: 1.0.1 kept the last good percentage, but before the first good reading there is none, and the app still sent 15 ("not available"), which the dash draws with the same warning icon. On Samsung/Android 15 the battery service can answer 0 or unknown at the start of a connection, keeping that window open. KawaNav now takes the level from Android's sticky `ACTION_BATTERY_CHANGED` broadcast (`EXTRA_LEVEL`/`EXTRA_SCALE`), with `BATTERY_PROPERTY_CAPACITY` as fallback, and while the phone-battery icon is on it sends no status-icon frame at all until there is a plausible reading.
- Ignored readings now log both raw values (sticky and property) and the held percentage, so a report with the exported log says what Android answered.

### Not yet tried on a bike
The fix was checked with the phone battery tests and against Android's sticky broadcast, not yet on a ride. A report of the icon still misbehaving should include Settings → "Export the log and the capture", a photo of the dash icon and the phone's real percentage. Unchanged from 1.0.2: the other values and warnings, what the two traction-control pairs report, which rotation rate is which axis ([docs/PROTOCOL.md](https://github.com/Darthbob/kawa-nav/blob/v1.0.3/docs/PROTOCOL.md)), the dashboard's capability answer, writing riding modes 5-7 in the debug build and the byte 88 wheel-speed setting.
