A ride's distance is now the odometer's and the GPS's together, and a few values the recorder wrote wrongly are gone. How KawaNav talks to the bike is unchanged from 0.9.2.

### Changed
- **Distance from the odometer and the GPS together**: the dash's odometer reads whole kilometres, so a ride measured by it alone moved in 1 km steps and could be almost a kilometre off. Now the odometer counts the kilometres and the GPS track fills in the part of a kilometre at each end of the ride; with only one of the two, that one alone. The test ride on a Z900 that read "13.00 km" now reads 13.2 km (its track alone measures 13.4), and the CSV's `dist_m` column no longer jumps 1000 m at each kilometre.
- **Rides saved before 0.9.3 are worked out again** when you open the log, or the ride itself, the same way as in 0.9.2: their distance and average speed may change a little.

### Fixed
- **A second ride no longer starts with a jump**: a ride recorded after another, without restarting the app, started its distance with everything ridden in between.
- **No more −60 °C oil**: in the first second or two after connecting, before the bike says which values it has, a temperature it does not have was read as −60 °C (oil) or −40 °C (coolant, intake). Temperatures now wait for the bike's answer, and a reading at the very bottom of the scale counts as none. A cell like that in a ride saved by an older version is ignored when it is read back.
- **The instant fuel consumption's "no value" (102.3)** is dropped instead of recorded.

### New, outside the app
- **[ride-report/](https://github.com/jackyes/kawa-nav/tree/v0.9.3/ride-report)**: a small Python tool for a computer that turns a "CSV (all values)" export into an HTML report, with every channel's lowest, average and highest, the notable moments, charts and the ride on an interactive map. It needs nothing but Python 3.9 or newer. A CSV exported by an older version can still hold a −60 °C oil cell, and the report draws it as a temperature; export the ride again from 0.9.3 and it is gone.

### Not yet tried on a bike
The new distance and the temperature rules were checked on a real Z900 ride file and in the tests, not yet on a ride recorded with 0.9.3. Unchanged from 0.9.2: what the two traction-control pairs report and which rotation rate is which axis ([docs/PROTOCOL.md](https://github.com/jackyes/kawa-nav/blob/v0.9.3/docs/PROTOCOL.md)), the dashboard's capability answer, writing riding modes 5-7 in the debug build, the byte 88 wheel-speed setting, and the Waze test while moving.

### Which APK
- **`KawaNav-v0.9.3.apk`**: the app for everyday use.
- **`KawaNav-v0.9.3-debug.apk`**: the same app with the test tools and the guarded writing of ride settings and shift lamp; tap the Settings title seven times. Both are signed with the same key, so one installs over the other and back, keeping rides, refuels, battery readings, the maintenance log and settings.

### Install / update
Open the APK on the phone (Android 13+). It updates 0.9.2 in place (and anything from v0.4 on) and keeps everything those versions saved. Known limitations: [README](https://github.com/jackyes/kawa-nav/blob/v0.9.3/README.md#-known-limitations).
